# ADR 0020 — gRPC and proto conventions

Status: Accepted — 2026-10-11 (revised 2026-10-24: two generated clients, breaking-change rule tied to 1.0; error mapping, IDs and pagination details accepted)

## Context

The `.proto` files are the source of truth for the public API, the runner protocol and the local socket (0003, 0005, 0008). Two generated clients: Rust (`kajiba-proto`, at build time) and TypeScript (UI, committed).

## Decision

- **buf** tooling: `buf lint`, `buf generate` (TypeScript only; Rust is generated by `kajiba-proto`'s `build.rs`), `buf breaking` against the last release tag; all run in `nix flake check`, including a check that the committed TypeScript matches a fresh `buf generate`.
- Packages: `kajiba.v1` (public API), `kajiba.runner.v1`, `kajiba.hook.v1` and `kajiba.admin.v1` (local socket only).
- **Before 1.0.0**, breaking changes are allowed in a minor bump (0023 rejects mismatched `0.minor` pairs) and `buf breaking` is informational. **From 1.0.0 on**: additive only within `v1`, otherwise a new `v2` package.
- Errors: standard gRPC codes; structured details through `google.rpc.Status` (`ErrorInfo` with domain `kajiba`, `BadRequest`, `PreconditionFailure`). Never a bare text message as the contract. Every error carries the request id in `ErrorInfo.metadata.request_id` (0022).
- **Error mapping**:

  | Situation                                       | Code                  | `ErrorInfo.reason`                                 |
  | ----------------------------------------------- | --------------------- | -------------------------------------------------- |
  | no or unknown credential                        | `UNAUTHENTICATED`     | `CREDENTIAL_INVALID`                               |
  | expired token or session                        | `UNAUTHENTICATED`     | `CREDENTIAL_EXPIRED`                               |
  | token lacks the method's scope                  | `PERMISSION_DENIED`   | `SCOPE_MISSING`                                    |
  | role too low on a visible resource              | `PERMISSION_DENIED`   | `ROLE_MISSING`                                     |
  | absent, or not visible to the caller            | `NOT_FOUND`           | `<RESOURCE>_NOT_FOUND` (`REPO_NOT_FOUND`…)         |
  | name already used                               | `ALREADY_EXISTS`      | `NAME_TAKEN`                                       |
  | invalid field (with `BadRequest`)               | `INVALID_ARGUMENT`    | `INVALID_FIELD`                                    |
  | change to a declared item (0014)                | `FAILED_PRECONDITION` | `DECLARED_IN_CONFIG`                               |
  | transition not allowed (cancel a finished run…) | `FAILED_PRECONDITION` | `INVALID_STATE`                                    |
  | client or runner version incompatible (0023)    | `FAILED_PRECONDITION` | `VERSION_INCOMPATIBLE`                             |
  | write barrier (0016), startup                   | `UNAVAILABLE`         | `MAINTENANCE`                                      |
  | anything else                                   | `INTERNAL`            | `INTERNAL` (no detail; logged with the request id) |

- Every list is paginated by **opaque cursor** (`page_size`, `page_token`, `next_page_token`). `page_size` 0 means 50, values above 200 are clamped to 200; the cursor encodes the sort key and the integer key of the last row (base64url), so pages are stable under concurrent inserts; order is fixed per method — by name for users and repositories, newest first (`id` descending) for runs, events and jobs; a malformed or foreign cursor is `INVALID_ARGUMENT`.
- Exposed identifiers are **opaque** ULIDs as text, stored in a unique `public_id` column (docs/schema.md); integer keys in the database, never exposed.
- Times as `google.protobuf.Timestamp`; durations as `google.protobuf.Duration`.
- Naming: singular resources in messages, `<Resource>Service` services, `Get/List/Create/Update/Delete` methods + explicit business verbs (`TriggerRun`, `CancelRun`). Each method declares its required scope as a method option (0014).
- Browser security: grpc-web calls have a non-simple `Content-Type`, so every cross-origin call triggers a CORS preflight; CORS allows only the forge's origin; session cookie `HttpOnly; Secure; SameSite=Strict`. No plain HTTP route mutates state, except the WebAuthn ceremonies protected by their challenge.

## Consequences

- The CLI and the frontend contain no manual type definitions.
- A contract break after 1.0.0 is a major version change (0023).

## Rejected alternatives

- protoc + plugins by hand: less reproducible, no `breaking`.
- Offset pagination: inconsistent under concurrent writes.
- `PERMISSION_DENIED` for invisible resources: reveals that they exist.
