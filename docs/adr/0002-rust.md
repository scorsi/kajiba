# ADR 0002 — Server and runner language: Rust

Status: Accepted — 2026-10-09

## Context

Candidates: Rust, Go, Zig, multi-language. Constraints: a single machine (Mac Mini M4 16 GB, aarch64 NixOS VM) where memory matters; showcase project; fear of compile times; Zig has no git/SSH/gRPC ecosystem.

## Decision

- Server and runner in **Rust** (stable toolchain).
- Cargo workspace (0018): `kajiba-core` (domain, permissions, events), `kajiba-git` (GitStore boundary), `kajiba-proto` (generated types), `kajiba-exec` (execution backends), `kajiba-server`, `kajiba-runner`. Utility subcommands (`serve-ssh`, `ssh-keys`, `hook`, `dump`, `admin`) live in the server binary.
- Stacks: tokio, axum + tonic (+ tonic-web), sqlx (SQLite), gix (0003), webauthn-rs, tracing.
- Compile comfort: `cargo check` in the loop, mold/lld linker in the devShell, crane on the Nix side (dependencies in a separate derivation), dev profiles without LTO.

## Consequences

- A single language for all server-side code; multi-language only shows up for the CLI (0007), justified by the shared gRPC schema.
- Low memory footprint, no external runtime in the VM.
- Longer compile times than Go; mitigated by the crate split.

## Rejected alternatives

- Go: excellent for a server that spawns many processes, fast builds; brings nothing Rust doesn't offer here, and the memory footprint is less favorable.
- Zig: no mature git, SSH or gRPC library; reserved for a possible low-level execution backend later.
