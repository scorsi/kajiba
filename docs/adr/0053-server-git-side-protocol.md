# ADR 0053 — Protocol between the server and the git side

Status: Accepted — 2026-10-25

## Context

ADR 0052 splits the forge into `kajiba-server` (database, API, gate) and `kajiba-git` (the only writer of `repos/`, parent of every git process that writes; naming in 0054). They talk over local sockets in both directions. This ADR fixes the sockets, the RPCs each side exposes, how versions are checked, and where the admission gate and `pending_push` live so that a crash of either side is recovered without inferring that a process has finished (0003). Each item below names the accepted ADR point it amends; everything else in those ADRs stands.

## Decision

### Sockets and transport

- gRPC over Unix sockets, as the admin socket today (tonic, peer credentials checked before any request, 0003). Three gRPC sockets and one raw one, owners and modes in 0052:
  - `/run/kajiba/local.sock` (server): `kajiba.admin.v1`, peers root and `kajiba-server` (identity amended by 0054); the git side never calls it.
  - `/run/kajiba/git.sock` (server): `kajiba.gate.v1`, peer `kajiba-git` only.
  - `/run/kajiba-git/local.sock` (daemon): `kajiba.git.v1` for the server and `kajiba.hook.v1` for the helpers (`ssh-keys` and the hooks), peers `kajiba-server` and `kajiba-git`. The daemon does not check which service a peer calls: both peers share the privilege domain the daemon serves, and the hook service does nothing a `kajiba.git.v1` caller could not already request. The helpers talk only to the daemon; the server's `git.sock` has one client, the daemon.
  - `/run/kajiba-git/ssh.sock` (daemon): the raw session hand-off from `kajiba-git serve-ssh`, peer `kajiba-git` only.
- **Hand-off.** `serve-ssh` parses `SSH_ORIGINAL_COMMAND` (J3 task 5), connects to `ssh.sock`, and sends one message carrying the user's public id from the forced command (`--user`, J3 task 4), the service (`upload-pack` or `receive-pack`), the repository address, and its standard input, output and error as file descriptors (`SCM_RIGHTS`). The daemon opens the session with the server (below), spawns `git <service>` on those descriptors, and answers with the child's exit status, or with a refusal message that `serve-ssh` prints to its standard error, once the child has exited; `serve-ssh` exits with that status. Killing `serve-ssh` does not touch the child: the daemon is its parent and the SSH connection's end-of-file ends the child. No bytes of the git stream pass through the daemon.

### Sessions

- A **session** is one child process of the daemon that may write a repository: `receive_pack`, `import` (the `fetch` of an `admin import`; the preceding `ls-remote` is not a session: it writes nothing), `maintenance` (`git gc`, J8). `upload_pack` over SSH is also a session so that the server authorises it and the daemon accounts for it, though it writes nothing. A session has a ULID `session_id`, a kind, a repository public id, the principal, the correlation id (0022) and the daemon's `generation`.
- **Every session is opened by the server** (`OpenSession`): the daemon never starts a child on its own. The server refuses (`PERMISSION_DENIED`/`ROLE_MISSING`, `NOT_FOUND`/`REPO_NOT_FOUND`, `FAILED_PRECONDITION`/`INVALID_STATE` for an archived repository, `UNAVAILABLE`/`MAINTENANCE` under the dump barrier, 0016) or returns the session with what the daemon needs and the server will not repeat: the repository public id, the default branch, the pusher's role and `is_admin`, and the `allowed_signers` text of the pusher's signing keys (0014). The daemon treats these as valid for the session only.
- The **generation** is a ULID the daemon draws at startup and sends in `Hello`. Children of an earlier generation cannot be alive: `KillMode=control-group` and systemd's restart sequence empty the unit's cgroup before a new `ExecStart` (0052). This is the only inference the protocol makes, and it is systemd's guarantee, not the row's age.

### RPCs

`kajiba.git.v1.GitService`, served by the daemon, called by the server:

| Method                 | Request → response                                                               | Daemon invariants                                                                                                                                                              |
| ---------------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `Hello`                | server version → daemon version, generation, live sessions                       | exact version equality (below); the answer is `ListSessions` at connection time                                                                                                |
| `ListSessions`         | — → sessions of this generation still running                                    | from the daemon's own child table, never from `/proc`                                                                                                                          |
| `CreateRepository`     | public id, default branch → —                                                    | ULID syntax; `repos/<id>.git` absent; `git init --bare` in `tmp/`, `core.sharedRepository=0640` (0052), `HEAD` set, `rename`, `fsync` (0012, 0032); `ALREADY_EXISTS` otherwise |
| `SetHead`              | public id, branch → —                                                            | repository present; branch name valid (0021); `HEAD` is written with git, never by writing the file                                                                            |
| `QuarantineRepository` | public id → destination                                                          | repository present; move to `tmp/orphans/` with numeric suffix and `fsync` (0032)                                                                                              |
| `ListRemoteRefs`       | source, credentials → branches and tags of the source                            | the isolation, deadline and credential rules of 0041 and 0044; nothing written                                                                                                 |
| `Fetch`                | session, public id, source, credentials, refs → — (returns when the child exits) | repository present and **without any ref**; refs under `refs/heads/` and `refs/tags/` only; `git fetch --atomic` of exactly those ids (0026); deadline of 0041                 |
| `Spawn`                | session, public id, service → exit status                                        | the SSH child of a hand-off that the server opened; `maintenance` runs `git gc --auto` (J8). Hooks are passed as `-c core.hooksPath=<store path>`, never per repository        |

`kajiba.hook.v1.HookService`, the contract J3 tasks 4 and 6 delivered in `kajiba-server`, now **served by the daemon** and called by `kajiba-git ssh-keys` and `kajiba-git hook pre-receive|post-receive`. Messages are unchanged except that the hook requests gain `session_id`; the daemon sets `KAJIBA_USER`, `KAJIBA_REPO` and `KAJIBA_SESSION` in the child's environment and the hooks forward them:

| Method        | Request → response                                                                           | Daemon behaviour                                                                                                                                                                                                                                                                                                                                             |
| ------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GetAuthKey`  | fingerprint → user public id and canonical key, or `NOT_FOUND`/`KEY_NOT_FOUND`               | forwarded to `GateService.GetAuthKey`; the daemon adds nothing                                                                                                                                                                                                                                                                                               |
| `PreReceive`  | user, repository, session, ordered updates, quarantine context → allowed or per-ref refusals | with the quarantine context: `git rev-list <new tips> --not <all refs>` once for the push, the fast-forward fact per update, the SSH signature of every selected commit and of every new annotated tag against the session's `allowed_signers` (0014); then one `GateService.PreReceive` carrying the updates and the facts; its answer is the hook's answer |
| `PostReceive` | user, repository, session, ordered updates → —                                               | one `GateService.PostReceive`; returns without waiting for `receive-pack` to exit (0003)                                                                                                                                                                                                                                                                     |

`kajiba.gate.v1.GateService`, served by the server on `git.sock`, called by the daemon only. Its `GetAuthKey`, `PreReceive` and `PostReceive` handlers are the ones J3 tasks 4 and 6 wrote for `kajiba.hook.v1`, moved to this service with the session and fact fields:

| Method          | Caller | Request → response                                                                                                       | Server behaviour                                                                                                                                                                                                                               |
| --------------- | ------ | ------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Hello`         | daemon | daemon version, generation → server version                                                                              | exact version equality; records the generation                                                                                                                                                                                                 |
| `GetAuthKey`    | daemon | fingerprint → user public id and canonical public key, or `NOT_FOUND`/`KEY_NOT_FOUND`                                    | active user's `auth` key only, `ssh_key.public_key` (J3 task 4)                                                                                                                                                                                |
| `OpenSession`   | daemon | user id, kind, repository address or public id → session, public id, default branch, role, `is_admin`, `allowed_signers` | redirects resolved (0021), archived refused (0026), role checked (`read` for `upload_pack`, `write` for `receive_pack`, 0014), barrier checked (0016), the session recorded in the in-memory gate                                              |
| `PreReceive`    | daemon | session, ordered updates with per-update fast-forward fact and signature verdict → allowed or per-ref reasons            | gate free for the repository (0003), ref names and prefixes (0013), role, non-fast-forward and deletion permissions, default branch protected, every signature verdict `verified`; then the `pending_push` row commits and only then `allowed` |
| `PostReceive`   | daemon | session → —                                                                                                              | wakes reconciliation (0003); no event is written here                                                                                                                                                                                          |
| `SessionExited` | daemon | session, exit status → —                                                                                                 | marks the process exited in the gate and reconciles that repository's pending rows (0003, 0037); idempotent                                                                                                                                    |

- **Import** (`kajiba.admin.v1`, root → server, unchanged for the operator): the server checks the target is declared, active and empty from its read access, calls `ListRemoteRefs`, commits the `pending_push` row (old = zero id, principal `system`, 0026), opens an `import` session and calls `Fetch`; when `Fetch` returns, the server marks the session exited and reconciles. The daemon re-checks emptiness itself before fetching.
- **Reconciliation at startup** (0026): creation calls `CreateRepository` and then commits the row; a default-branch change calls `SetHead`; the orphan sweep (0032) lists `repos/`, compares with the `repo` table and calls `QuarantineRepository` for each unregistered directory. A directory created for a reconciliation that then aborts is an orphan at the next start; no removal RPC exists.
- Each side exposes only what the table says. The daemon has no `Delete`, no arbitrary `git` command, no path argument: every request names a repository by public id and the daemon builds the path. The server exposes no database access to the git side: `GetAuthKey` and `OpenSession` return what a session needs and nothing else.

### Versioning

- Both binaries come from one package set of one flake revision (0018, 0023) and are deployed together. `Hello` in both directions carries the `VERSION` string; **exact equality is required**, stricter than 0023's matrix, because the two sides share no compatibility window: a mismatch is a half-applied `nixos-rebuild switch`. A mismatch is refused with `FAILED_PRECONDITION`/`VERSION_INCOMPATIBLE` naming both versions (0020), logged once, and the connecting side retries with capped backoff until the other unit has restarted. Protos stay in `proto/` under the usual `buf` checks (0020); before 1.0 they change freely in a minor bump, as any `kajiba.*` package.

### Durability and recovery

- **The admission gate and `pending_push` stay in the server**, as 0003 and 0037 describe; the daemon holds only its child table, in memory, exact for its generation. The gate's in-memory set of "repositories with a live admitted process" is now fed by `OpenSession` and `SessionExited` and rebuilt from `ListSessions` on every connection to the daemon.
- A pending row is reconciled only when the server knows that no session of its repository is alive, by one of two exact facts: the daemon reported `SessionExited`, or the session belongs to an earlier daemon generation than the one connected. Row age, connection drops and `/proc` are never used.
- Recovery matrix:
  - **Daemon crashes or restarts**: its children die with its cgroup (0052). On reconnect the server receives a new generation and an empty or partial session list; every pending row of an earlier generation is reconciled: applied refs give one event each, unapplied give none, unexpected values retain the row (`push-retained`, 0036). A push whose `receive-pack` died mid-way is refused to the user by `serve-ssh` and replayed by the user.
  - **Server crashes or restarts**: the daemon keeps its children; `serve-ssh` sessions keep running (hooks that cannot reach the server fail closed: `pre-receive` refuses, `post-receive` logs). At startup the server connects, learns the live sessions, and reconciles only the pending rows of repositories without a live session; the others reconcile at their `SessionExited`, which the daemon sends when the server is back (it retries `SessionExited` until acknowledged or until the server's `Hello` shows it already learned the fact from `ListSessions`).
  - **Both down**: at the next start no session of the new generation exists; every pending row is reconciled.
  - **Daemon reachable but the server never opened the session** (a `serve-ssh` while the server is down): refused before any child starts; nothing to recover.
- **Dump barrier (0016, J8)**: the barrier is server-side only. Closing admission refuses `OpenSession` for `receive_pack`, `import` and `maintenance` with `UNAVAILABLE`/`MAINTENANCE` and `PreReceive` for sessions already open; draining waits for `SessionExited` of every open writing session and for their reconciliation; the snapshot and the repository copy are then taken by the server from its read access. `upload_pack` sessions are not refused. The daemon needs no barrier state.

### Amended points

- **0003**: the hook's one call goes to the daemon; the gate learns process exits from `SessionExited`; the local socket paragraph is replaced by the inventory above. `kajiba.hook.v1` leaves the server's `local.sock`, which carries `kajiba.admin.v1` only.
- **0014**: the signature algorithm runs in the daemon with `allowed_signers` from `OpenSession`; the server verifies the verdicts are present and the policy that needs no object.
- **0016**: as the dump barrier paragraph above.
- **0020**: packages added: `kajiba.git.v1`, `kajiba.gate.v1` (local sockets only, like `kajiba.hook.v1` and `kajiba.admin.v1`); error mapping row added: git side unreachable or version refused → `UNAVAILABLE`, reason `GIT_SIDE_UNAVAILABLE`.
- **0022**: events added. Server: `git-side-connected{version,generation}`, `git-side-unavailable{err}` (warn), `git-side-version-refused{local,remote}` (error). Daemon: `start`, `ready`, `stopping`, `fatal`, `config-invalid` as the server; `server-connected{version}`, `server-unavailable{err}` (warn); `session-started{session,kind,repo}`, `session-exited{session,kind,repo,status}`; `repo-created{repo}`, `repo-quarantined{path,destination}` (warn) mirror the server's lines for the same acts, with `repo` the public id, since the daemon knows no names.
- **0026**, **0041**, **0044**: import as above; the 0041 isolation and deadline rules apply to the daemon's children; the credential string of 0044 travels in the `Fetch` and `ListRemoteRefs` requests and is dropped with them.

## Consequences

- One hook call still produces one admission decision, backed by one `pending_push` commit, with the same guarantee as 0003: every applied ref has exactly one durable event before a later push can advance it, assuming durable storage and no out-of-band ref writes.
- The hook's quarantine context (J3 task 6) is consumed by the daemon, not by the server; the server never reads quarantined objects.
- Tests can drive the server with a fake `GitService` and the daemon with a fake `GateService`: each side's contract is a proto, mockable in Rust integration tests before the nixosTests.

## Rejected alternatives

- Hooks calling the server directly: no process on the server side can read the quarantine (0052).
- Streaming the git byte stream through the daemon instead of passing descriptors: a copy loop, chunked protobuf framing and backpressure for every clone and push, to obtain what three descriptors give for free.
- The daemon owning the gate and the pending rows: a second SQLite writer or a second store, and the events of 0017 would be written by a process that cannot write the journal.
- Loose version compatibility between the two sides: there is no deployment where they differ except mid-switch.
- A daemon-side barrier flag for dumps: every writing session already asks the server first.
