# ADR — kajiba (鍛冶場)

Architecture decisions of the forge. Format: status, context, decision, consequences, rejected alternatives. **Until implementation starts (J1), ADRs are revised in place** and the revision is dated in their status line; from then on an accepted ADR is not modified, it is superseded by a new one that references it. Decisions taken during a milestone or a review are recorded as one ADR per theme, never one ADR per event.

Statuses: **Accepted** (decided by the owner: 2026-10-09, 2026-10-11, revisions of 2026-10-24, split of 2026-10-25), **Proposed** (to confirm), **Open** (point left for later).

The ADRs describe the product. Values of a particular deployment (hosts, ports, secrets, which repositories it hosts, off-host backup) live in that deployment's repository.
