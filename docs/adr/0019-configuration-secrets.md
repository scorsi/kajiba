# ADR 0019 — Configuration and runtime secrets

Status: Accepted — 2026-10-11

## Context

Server and runner are deployed exclusively through Nix (NixOS, nix-darwin). Secrets are provided by sops as files. Environment variables easily leak into logs and `ps`.

## Decision

- One **TOML file** per component, **generated by the Nix module** (never written by hand), passed through `--config <path>`. The TOML schema is defined by a single Rust struct (serde); the Nix module options mirror it one to one.
- **No secret in the file**: only paths (`mirror.token_file`, `runners.<name>.token_file`, `signing.key_file`, …) read at startup or on demand. Files are owned by the `kajiba` user, mode 0400.
- No configuration through environment variables, except `RUST_LOG` (verbosity) and the runtime's standard variables.
- Safe defaults in the code; the Nix module only writes what differs.
- Reload: service restart (`switch`), no hot reload.

## Consequences

- The configuration is versioned in sekkeizu and reproducible.
- A unit test checks that the complete example configuration deserializes; a `nixosTest` checks that the module produces a configuration accepted by the binary (`kajiba config check`).

## Rejected alternatives

- CLI flags for everything: unreadable in a Nix module.
- Environment variables: secret exposure, no structure.
