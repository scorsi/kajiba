# kajiba — milestone plan

Technical milestones, no calendar. Each milestone has a verifiable **deliverable**, explicit **acceptance criteria**, the **tests** that prove them, and the **delegable** part (tests, boilerplate, refactoring). A milestone is closed when its criteria pass on `aarch64-linux` in `nix flake check` and, from J4, in the `e2e` job (0015); a milestone never leaves `nix flake check` red in between. Checks that need a real deployment are not product criteria: they belong to the deployment repository.

ADR references in parentheses. nixosTest names are flake attributes `checks.<linux system>.<name>`.

**Delivery order** (owner decision, 2026-10-30): J6 is delivered before J5. Milestone numbers stay as they are because ADRs reference them; the CI pages of the UI belong to J5.

## J0 — Skeleton: a green repository at the first commit (done)

**Deliverable**: the `kajiba` monorepo (0018) with a GitHub mirror, `nix flake check` green, no feature.

## J3 — The server/git-side split, then writes over SSH, hooks, permissions, signatures

**Deliverable**: the forge runs as two units and two users (0052): `kajiba-server` never writes a repository, `kajiba-git` is the only writer and owns the SSH path; then `git push` over SSH, controlled by permissions and ref rules, with mandatory signatures.

Content: the split of 0052–0054 is built first, with J2's repository writes (reconciliation creation and `HEAD`, orphan quarantine, `admin import`) moved behind the git side's daemon and its sessions (0053) before any push is accepted. Then the SSH path: dedicated sshd instance in the module logging in as `kajiba-git`, `AuthorizedKeysCommand` → `kajiba-git ssh-keys`, `kajiba-git serve-ssh` handing its descriptors to the daemon, which spawns `git receive-pack`/`upload-pack` (0004, 0053); keys come from the configuration (0014), no key-mutating RPC; `kajiba-git hook pre-receive|post-receive` → `kajiba.hook.v1` on the daemon's socket, which runs the object-dependent checks in the quarantine and calls `kajiba.gate.v1.PreReceive` on the server, which keeps the policy, the admission gate and `pending_push` reconciliation (0003, 0026, 0052, 0053); global `core.hooksPath`; read/write/admin RBAC + `is_admin`, repository permissions from the configuration (0014, 0026); ref rules of 0013/0014, fixed by the product, per-pattern rules declared only (0026); signature algorithm of 0014 run by the daemon with `allowed_signers` from `OpenSession`; `push` events (0017); `/readyz` checks the git-side link and the sshd integration. `AuthorizedKeysCommand` prints the forced-command line of 0004 (`command="kajiba-git serve-ssh --user <public id>",restrict <key>`) whose key part is the canonical stored key (`ssh_key.public_key`, no comment), never the configured line. Tasks 1–2 close the two read-path bounds that only a repository writer can exercise (J2 review); tasks 3–6 were delivered in `kajiba-server` before the split decision and move to `kajiba-git` in task 16.

Ordered tasks; each is one feature, closable in one sitting with its tests, in one commit, and leaves `nix flake check` green. Tasks 1–6 are done and record the pre-split server identity. Tasks 7–16 build the split; no SSH write is accepted before tasks 17–23 are complete; the final two tasks split the acceptance coverage between `nixos-git-ssh` and `nixos-git-ssh-recovery`. No automatic migration of a J2 layout is needed: nothing is deployed; nixosTests start from the new layout (0052).

Tests: an oversized ancestor beyond the returned page and at a cursor boundary cannot induce an unbounded read through an accepted push; valid histories retain their ordering and pagination; header kind and size boundaries are checked before loading the affected objects.

Tests: large author fields and many parents shorten a page even with tiny messages; exact budget boundary, continuation without skipped or repeated commits, and a final empty page with no token.
3. **Repository role checks** (0013, 0014, 0026, 0028): one shared permission check over reconciled identity and repository permissions, including implicit owner `admin`, global `is_admin`, disabled users and the prohibition on external-user writes; no permission mutation API. Tests: the read/write/admin matrix, owner and global admin, disabled or external user, removed permission and archived repository.
4. **SSH auth-key lookup and `ssh-keys`** (0003, 0004, 0014, 0028): fingerprint lookup over the local socket resolves an active user's auth key; implement `kajiba-server ssh-keys <fingerprint>` under 0004's `AuthorizedKeysCommand` contract using the canonical stored `ssh_key.public_key`, without a comment or configured-line text. Tests: known auth key, unknown fingerprint, signing-only key, disabled user, removed or reassigned declared key, configured comments/options never echoed, and the output contract of 0004.

Tests: ordered update parsing including zero ids, malformed input/context, one call per invocation, missing socket gives an explicit failure, no hook service on the public listener, admin transport still works, and socket access remains restricted; proto lint and generated-code freshness checks.
7. **Rename the GitStore library** (0002, 0018, 0054): rename `kajiba-git` to `kajiba-gitstore` and `crates/kajiba-git/` to `crates/kajiba-gitstore/` before creating the new binary crate; update workspace members, dependency paths and package names, Rust imports, lockfile, tests, fixtures, Nix references, `versions-identical`, `CLAUDE.md` and `CONTRIBUTING.md` where they name the library. **Acceptance criteria** (`nixos-ci-*`, nodes `forge` + `runner`, forge behind an nginx TLS front with a test CA, Nix closure preloaded)

- Signed push on `main` of a repository in CI mode `push` → run created, executed, success; failing `flake check` → run failed with logs, and the CLI prints the failing check, the reason and the last 20 log lines on stderr.
- Sources reach the runner only as bundles over its authenticated channel: the forge's request log shows no smart HTTP request from `runner`, and a second run of the same repository transfers only the new commits.
- Push on `refs/contrib/*` (injected in test by the forge) → no run; manual `TriggerRun` on that sha by a `write` user → run; by a `read` user → `ROLE_MISSING`.
- `kajiba-server` restart during a job → the runner reconnects, the job finishes, the result is recorded exactly once; no log chunk lost or duplicated.
- Runner frozen or killed during a job → lease expired → attempt `lost`, then a new attempt on a compatible runner if replayable; a late result from the old attempt is ignored.
- Job no connected runner can take → stays "pending" with its reason (`no-connected-runner` while the runner is stopped).
- The journal holds `run-created`, `run-started`, `run-finished`, `attempt-lost`, `attempt-replayed`, `runner-connected`, `runner-disconnected` and `runner-refused` for the scenarios above.
- CLI: `ci run` follows and exits 0 on success, 1 on failure; `ci run --detach` prints the run id at once; `ci status` exits 75 while the run is pending or running; `ci watch` re-attaches and exits with the run's code; `kajiba ci logs … | head -n 1` exits quietly.
- `kajiba-server admin retention` with a short `ci.log_retention` deletes old logs and keeps their runs.
- Runner journal passes `nisshi validate --logs`.
- Worktree (`nixos-ci-worktree`): from `client`, with uncommitted changes, `kajiba ci run --worktree` as a `write` user with a `ci:trigger` PAT → run on `runner`, logs streamed, exit 0; a change that breaks a check → exit non-zero with logs; no new ref, branch or stash on the forge or the clone, and the captured commit is not fetchable over git transport.
- Worktree: `--check a` builds only `checks.<system>.a`; a check with `requiredSystemFeatures = [ "kvm" ]` runs only on a runner tagged `kvm`.
- Worktree: `read` user → `ROLE_MISSING`; PAT without `ci:trigger` → `SCOPE_MISSING`; bundle above 64 MiB → `BUNDLE_TOO_LARGE`; no declared runner for the system → `NO_MATCHING_RUNNER`; the run and its bundle are gone after `ci.worktree_retention`.

**Delegable**: test machinery (minimal flake with a trivial check, store preloading), lease/reconnection tests, proto message boilerplate.
