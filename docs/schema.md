# kajiba — relational schema v0

Status: Accepted — 2026-10-24. Reference for migration `0001` (ADR 0012, 0013). Later milestones add columns through new migrations; this file is updated with them.

## Conventions

- `id INTEGER PRIMARY KEY` everywhere, never exposed. Exposed entities add `public_id TEXT NOT NULL UNIQUE`: a ULID (26 characters, Crockford base32, upper case) generated by the server at insert (0020).
- Times: `INTEGER` milliseconds since the Unix epoch, UTC. Booleans: `INTEGER NOT NULL CHECK (x IN (0, 1))`.
- Closed value sets: `TEXT` with a `CHECK (... IN (...))`. No triggers, no JSON1 (0012); JSON is opaque `TEXT`.
- Names (`user.name`, `repo.name`, runner names): lower case, `[a-z0-9][a-z0-9._-]{0,62}`, validated by the shared validator (0021) and stored lower case.
- Hashes: `BLOB` SHA-256 of the secret. Secrets themselves are never stored.
- `source`: `config` (declared, reconciled at startup, read-only through the API) or `runtime`.
- `ON DELETE CASCADE` for owned rows, `RESTRICT` where a deletion must be explicit.

## Identity (0014)

| Table                 | Columns                                                                                                                                                                          | Constraints                                                                                    |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `user`                | `id`, `public_id`, `name`, `kind` (`local`, `external`), `is_admin`, `source`, `created_at`, `disabled_at` NULL                                                                  | `UNIQUE(name)`; `external` ⇒ `is_admin = 0` (CHECK)                                            |
| `ssh_key`             | `id`, `public_id`, `user_id` → user CASCADE, `usage` (`auth`, `signing`), `key_type`, `public_key`, `fingerprint` (`SHA256:…`), `source`, `created_at`, `last_used_at` NULL      | `UNIQUE(fingerprint, usage)` (an auth key resolves to one user)                                |
| `api_token`           | `id`, `public_id`, `user_id` → user CASCADE, `name`, `token_hash`, `scopes` (space-separated), `source`, `created_at`, `expires_at` NULL, `last_used_at` NULL, `revoked_at` NULL | `UNIQUE(token_hash)`, `UNIQUE(user_id, name)`                                                  |
| `webauthn_credential` | `id`, `public_id`, `user_id` → user CASCADE, `credential_id` BLOB, `passkey` (serialized by webauthn-rs, opaque), `name`, `created_at`, `last_used_at` NULL                      | `UNIQUE(credential_id)`                                                                        |
| `session`             | `id`, `user_id` → user CASCADE, `token_hash`, `created_at`, `expires_at`, `last_seen_at`                                                                                         | `UNIQUE(token_hash)`; index `(expires_at)`                                                     |
| `enrollment_token`    | `id`, `user_id` → user CASCADE, `token_hash`, `created_at`, `expires_at`, `consumed_at` NULL                                                                                     | `UNIQUE(user_id)` (one outstanding link per user; a new one replaces it), `UNIQUE(token_hash)` |

WebAuthn ceremony challenges live in memory with a 5-minute TTL; a restart only makes the user start the ceremony again.

## Repositories (0011, 0021)

| Table             | Columns                                                                                                                                                                                                                                                                     | Constraints                                                                                                       |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `repo`            | `id`, `public_id` (also the directory name, 0012), `owner_id` → user RESTRICT, `name`, `visibility` (`public`), `ci_enabled`, `default_branch`, `description`, `created_at`                                                                                                 | `UNIQUE(owner_id, name)`                                                                                          |
| `repo_redirect`   | `id`, `owner_name`, `name`, `repo_id` → repo CASCADE, `created_at`                                                                                                                                                                                                          | `UNIQUE(owner_name, name)`; creating or renaming a repo to that pair deletes the redirect in the same transaction |
| `repo_permission` | `user_id` → user CASCADE, `repo_id` → repo CASCADE, `role` (`read`, `write`, `admin`)                                                                                                                                                                                       | `PRIMARY KEY(user_id, repo_id)`                                                                                   |
| `mirror`          | `id`, `public_id`, `repo_id` → repo CASCADE, `remote_url`, `credential` (name in `mirror.credentials`, 0019), `enabled`, `state` (`idle`, `queued`, `running`), `redo`, `attempts`, `next_attempt_at` NULL, `last_success_at` NULL, `last_error` NULL, `last_error_at` NULL | `UNIQUE(repo_id, remote_url)`; index `(state, next_attempt_at)`                                                   |

The owner of a repository has the `admin` role implicitly; `repo_permission` holds the others.

## Events (0003, 0017)

| Table                | Columns                                                                                                                                                                                                                                      | Constraints                                                              |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| `event`              | `id` (sequence), `public_id`, `kind`, `version`, `occurred_at`, `principal_kind` (`user`, `runner`, `system`), `principal_id` NULL, `repo_id` NULL (no foreign key: the journal outlives deletions), `correlation_id`, `payload` (JSON text) | append-only: never updated or deleted by the code; index `(repo_id, id)` |
| `handler_checkpoint` | `handler` (stable name: `ci`, `mirror`, …), `last_event_id`, `updated_at`                                                                                                                                                                    | `PRIMARY KEY(handler)`                                                   |
| `pending_push`       | `id`, `repo_id` → repo CASCADE, `principal_id` → user, `correlation_id`, `updates` (ordered JSON array: ref, old sha, new sha; zero sha = absent), `created_at`                                                                              | `UNIQUE(repo_id)` (one admitted push per repository)                     |

Pending rows are reconciled in `id` order, refs in array order, only after their `receive-pack` has exited (0003). Event insertion and pending-row deletion commit together; the repository admits no further ref mutation until reconciliation completes. Unexpected ref values retain the row and block admission.
