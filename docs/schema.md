# kajiba — relational schema v0

Status: Accepted — 2026-10-24. Reference for migration `0001` (ADR 0012, 0013). Later milestones add columns through new migrations; this file is updated with them.

## Conventions

- `id INTEGER PRIMARY KEY` everywhere, never exposed. Exposed entities add `public_id TEXT NOT NULL UNIQUE`: a ULID (26 characters, Crockford base32, upper case) generated by the server at insert (0020).
- Times: `INTEGER` milliseconds since the Unix epoch, UTC. Booleans: `INTEGER NOT NULL CHECK (x IN (0, 1))`.
- Closed value sets: `TEXT` with a `CHECK (... IN (...))`. No triggers, no JSON1 (0012); JSON is opaque `TEXT`.
- Names (`user.name`, `repo.name`, runner names): lower case, `[a-z0-9][a-z0-9._-]{0,62}`, validated by the shared validator (0021) and stored lower case.
- Hashes: `BLOB` SHA-256 of the secret. Secrets themselves are never stored.
- `source`: `config` (declared, reconciled at startup, read-only through the API) or `runtime`, on tables that hold both (`user`, `ssh_key`, `api_token`).
- Declarative vs runtime (0026): `repo`, `repo_redirect`, `repo_permission`, the configuration columns of `mirror` and the `runner` row with its `capabilities` hold declared rows only, written by startup reconciliation and never by the API; they need no `source` column. Everything else is runtime state, including the runtime columns of `mirror` and `runner`.
- `ON DELETE CASCADE` for owned rows, `RESTRICT` where a deletion must be explicit.

| `session`             | `id`, `user_id` → user CASCADE, `token_hash`, `created_at`, `expires_at`, `last_seen_at`, `step_up_at` NULL (0143)                                                               | `UNIQUE(token_hash)`; index `(expires_at)`                                                     |

WebAuthn ceremony challenges live in memory with a 5-minute TTL; a restart only makes the user start the ceremony again.

## Repositories (0011, 0021)

| Table             | Columns                                                                                                                                                                                                                                                                                                                        | Constraints                                                                                                                                |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `repo`            | `id`, `public_id` (also the directory name, 0012), `config_key` (stable declared key, 0026), `owner_id` → user RESTRICT, `name`, `visibility` (`public`), `default_branch`, `description`, `created_at`, `archived_at` NULL (0026), `ci_mode` (`off`, `manual`, `push`; 0133)                                                  | `UNIQUE(config_key)`; `UNIQUE(owner_id, name)` over every row (an archived repository keeps its name, 0026)                                |
| `repo_redirect`   | `id`, `owner_name`, `name`, `repo_id` → repo CASCADE, `created_at`                                                                                                                                                                                                                                                             | `UNIQUE(owner_name, name)`; rows equal the declared `previous_names` of an active repository, kept as they were for an archived one (0026) |
| `repo_permission` | `user_id` → user CASCADE, `repo_id` → repo CASCADE, `role` (`read`, `write`, `admin`)                                                                                                                                                                                                                                          | `PRIMARY KEY(user_id, repo_id)`                                                                                                            |
| `mirror`          | `id`, `public_id`, `repo_id` → repo CASCADE, `remote_url`, `credential` (name in `mirror.credentials`, 0019), `enabled`, `state` (`idle`, `queued`, `running`), `redo`, `attempts`, `next_attempt_at` NULL, `last_success_at` NULL, `last_error` NULL, `last_error_at` NULL, `prepared_digest` NULL, `prepared_at` NULL (0027) | `UNIQUE(repo_id, remote_url)`; index `(state, next_attempt_at)`                                                                            |

The owner of a repository has the `admin` role implicitly; `repo_permission` holds the others.

Declared (0026): `repo` except `public_id` and `created_at`; `repo_redirect`; `repo_permission`; `mirror.remote_url`, `credential`, `enabled`. A mirror is identified by `(repo_id, remote_url)`: changing the URL is a new mirror. Runtime: the other `mirror` columns, kept across reconciliations. A repository removed from the configuration is archived (0026): its row stays with `archived_at` set (metadata, code browsing, CI history, mirror rows and status stay readable; its permissions are deleted; its redirects are kept and their names stay locked; its mirrors stop syncing) and its directory stays in place; git transport and `/raw/` are refused for it. Re-declaring the same key clears `archived_at` on the same row, content intact. Queries that admit git access, CI or mirroring filter on `archived_at IS NULL`; listings and lookups do not. The J2 migration adds `config_key` (with a unique index) and `archived_at` by `ALTER TABLE … ADD COLUMN`; `UNIQUE(owner_id, name)` from migration 3 already covers every row, so `repo` needs no rebuild. The code never writes `config_key` empty.

Migration 12 widens `run.trigger` and adds `run.checks` by rebuilding `run`; because sqlx runs SQLite migrations in a transaction where foreign keys stay on, the tables under `run` (`job`, `job_attempt`, `step`, `log_chunk`, `artifact`) are copied, dropped leaf first and recreated unchanged around the rebuild. A worktree run has no `ref` and no `event_id`; its bundle is `ci/bundles/<run public id>.bundle` (0097).

## Events (0003, 0017)

| Table                | Columns                                                                                                                                                                                                                                                             | Constraints                                                              |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| `event`              | `id` (sequence), `public_id`, `kind`, `version`, `occurred_at`, `principal_kind` (`user`, `runner`, `system`), `principal_id` NULL, `repo_id` NULL (no foreign key: the journal outlives deletions), `correlation_id`, `payload` (JSON text)                        | append-only: never updated or deleted by the code; index `(repo_id, id)` |
| `handler_checkpoint` | `handler` (stable name: `ci`, `mirror`, …), `last_event_id`, `updated_at`                                                                                                                                                                                           | `PRIMARY KEY(handler)`                                                   |
| `pending_push`       | `id`, `repo_id` → repo CASCADE, `principal_id` → user NULL (NULL = `system`, `admin import`, 0026), `correlation_id`, `updates` (ordered JSON array: ref, old sha, new sha; zero sha = absent), `created_at`, `git_session_id` NULL (unique), `git_generation` NULL | `UNIQUE(repo_id)` (one admitted push per repository)                     |

A reserved import records `git_session_id` before Fetch; `OpenSession` records the daemon generation before any child starts (0053). `SessionExited` clears the session id durably. A row with a session and generation waits for that exit or a replacement generation, including across server restarts.

Pending rows are reconciled in `id` order, refs in array order, only after their `receive-pack` has exited (0003). Event insertion and pending-row deletion commit together; the repository admits no further ref mutation until reconciliation completes. Unexpected ref values retain the row and block admission.
